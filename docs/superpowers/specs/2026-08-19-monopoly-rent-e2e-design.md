# Monopoly 2× Rent (Full-Set Doubling) E2E Test — Design

## Assumptions (author was unavailable — please verify)

1. **Feature under test**: the existing reducer rule that owning a complete color
   group (a "monopoly" / full set) doubles rent on that group's properties.
   In `src/logic/gameReducer.ts`, `ResolveSpace` for a Property computes
   `rent = calculatePropertyRent(space)`, then `monopoly = isMonopoly(owner, board, space)`
   and `if (monopoly) rent *= 2`, logging `LogEventKey.MonopolyRent`
   (`"{{owner}} owns the full color group — {{name}}'s rent doubles!"` in en).

2. **Determinism via the seeder**: dice rolls are random on the real server
   (even "aimed" rolls only weight toward the target via `rollControlledDice`),
   so a UI-only test cannot reliably land a player on a rented property. The
   established pattern is to seed the decision point directly — `seedGame`
   posts a full `GameState` to `POST /seed` (enabled by `E2E_SEED_ENABLED=true`
   in the e2e server fixture). The existing `e2e/fixtures/bankruptcy-seed.ts`
   seeds a `Resolving` phase with a pre-computed `PayRent` pending action; this
   test does the same for the doubled-rent case.

3. **Scenario**: Alpha owns the full Dark Blue set (Park Place id 37 +
   Boardwalk id 39). Bravo (current player, id 1) is standing on Boardwalk and
   owes doubled rent: Boardwalk base rent `50` → `100`. Bravo can afford it and
   pays. After payment the money transfers and the event log shows both the
   doubling message and the paid-rent message.

4. **New generated fixture** `e2e/fixtures/monopoly-rent-seed.ts` produced by a
   new `scripts/print-monopoly-rent-seed.ts` + `npm run print-monopoly-rent-seed`,
   following the `bankruptcy-seed` convention: generated code, pure literals,
   only an `import type { GameState }` line (Playwright's ESM loader rejects bare
   JSON imports from `src/data/*`).

5. **New spec file** `e2e/monopoly-rent.spec.ts` with one test. The expected
   doubled amount is computed from the fixture's own board data
   (`board[39].rent[0] * 2`) rather than a magic literal, so the assertion
   stays correct if the board data changes.

## Background

- **Reducer doubling** (`src/logic/gameReducer.ts`): `isMonopoly(ownerId, board,
  space)` from `src/logic/rent.ts` returns true when every property sharing the
  landed space's `color` is owned by the same player. When true the pending rent
  is doubled and a `MonopolyRent` log entry is emitted with
  `params: { owner, name }`.
- **i18n (en)**: `event.monopolyRent` = "{{owner}} owns the full color group —
  {{name}}'s rent doubles!"; `event.paidRent` = "{{name}} paid {{amount}} rent
  to {{owner}}"; `action.payRentLabel` = "Pay rent"; `action.payRent` = "Pay
  Rent". Both `en` and `id` locales already contain these keys — no new strings.
- **Money formatting** (`src/data/currency.ts`): compact notation
  (`Intl.NumberFormat`). USD: `100` → `$100`, `1100` → `$1.1K`, `1400` →
  `$1.4K`, `1500` → `$1.5K`, `1000` → `$1K`.
- **Seed validation** (`src/logic/seed.ts`): board must have 40 spaces;
  `turnOrder` must be a permutation of the player ids; `currentPlayer` must be in
  `turnOrder`; every owned board space must match each player's `properties`
  list; money must be a non-negative finite number; a `Resolving` phase requires
  a non-null `pendingAction`; a `Waiting` phase requires `pendingAction === null`
  and `dice === null`. No constraint on `dice` in `Resolving`.
- **Room validation** (`validateStateForRoom`): `players.length` must equal the
  number of joined slots; `players[i].id === i` for every joined slot; the
  `currentPlayer` slot must be connected or a bot.
- **Server seeding** (`server/gameServer.ts` `seedState`): validates, replaces
  the room's state wholesale (preserving the room's `tradesEnabled`), broadcasts
  to all clients, and calls `driveBots()` (no-op when the current player is a
  connected human).
- **Event log UI** (`src/components/EventLog.tsx`): renders the last 2 entries
  by default; entries carry `data-testid="event-entry"`. Entries are interpolated
  by `src/i18n/log.ts` (`resolveLogEntry`), which formats `amount` via
  `formatMoney`.
- **Rent prompt UI** (`src/components/ActionSection.tsx`): for a `PayRent`
  pending action renders `Pay rent <strong>$100</strong>` and a `Pay Rent`
  button (disabled when unaffordable). The current player's card shows
  `formatMoney(player.money)` (`data-testid="player-card"`).

## Design

### 1. Generator script — `scripts/print-monopoly-rent-seed.ts`

Same shape as `scripts/print-seed.ts` (semicolons; writes a `// GENERATED by
npm run print-monopoly-rent-seed — do not edit by hand.` header):

```ts
import { writeFileSync } from 'node:fs';
import { createSeededState } from '../src/logic/seed';
import { GamePhase, LogEventKey, PendingActionType } from '../src/types/game';

const BOARDWALK = 39; // id 39: rent[0] === 50
const PARK_PLACE = 37;

const state = createSeededState({
  players: [
    { id: 0, name: 'Alpha', money: 1000, passedGo: true },
    { id: 1, name: 'Bravo', money: 1500, passedGo: true },
  ],
  board: {
    37: { owner: 0 },
    39: { owner: 0 },
  },
  currentPlayer: 1,
  turnOrder: [1, 0],
  phase: GamePhase.Resolving,
  pendingAction: {
    type: PendingActionType.PayRent,
    spaceId: BOARDWALK,
    amount: 50 * 2, // base rent doubled by the full color group
  },
  tradesEnabled: false,
});

// Seed the doubling message so the log shows why the rent is doubled.
state.eventLog = [
  { key: LogEventKey.MonopolyRent, params: { owner: 'Alpha', name: 'Bravo' } },
];

const out =
  "import type { GameState } from '../../src/types/game'\n" +
  '\n' +
  '// GENERATED by `npm run print-monopoly-rent-seed` — do not edit by hand.\n' +
  '// Alpha owns the full Dark Blue set (37 + 39); Bravo owes $100 on Boardwalk (base $50 x2).\n' +
  `export const monopolyRentSeed: GameState = ${JSON.stringify(state, null, 2)}\n`;

writeFileSync('e2e/fixtures/monopoly-rent-seed.ts', out);
console.log('wrote e2e/fixtures/monopoly-rent-seed.ts');
```

The amount is `50 * 2` because `board-data.json` id 39 has `rent: [50, 200, 600,
1400, 1700, 2000]` and `color: "#00008B"` (Dark Blue, shared with id 37).
`createSeededState` derives each player's `properties` from the board overrides,
so Alpha's `properties` become `[37, 39]` automatically.

Add npm script `print-monopoly-rent-seed` to `package.json`.

### 2. Generated fixture — `e2e/fixtures/monopoly-rent-seed.ts`

Output of the script (committed, generated). Pure literals; only
`import type { GameState }`.

### 3. E2E spec — `e2e/monopoly-rent.spec.ts`

No semicolons (matches the `e2e/*` convention). One test:

```ts
import { test, expect } from './fixtures'
import { seedGame } from './helpers/seed'
import { monopolyRentSeed } from './fixtures/monopoly-rent-seed'

test('a full color group doubles rent and the renter pays it', async ({ browser, serverUrl }) => {
  const context = await browser.newContext()
  await context.addInitScript(() => {
    localStorage.setItem('monopoly-language', 'en')
    localStorage.setItem('monopoly-currency', 'USD')
  })
  const contextB = await browser.newContext()
  await contextB.addInitScript(() => {
    localStorage.setItem('monopoly-language', 'en')
    localStorage.setItem('monopoly-currency', 'USD')
  })
  const pageA = await context.newPage()
  const pageB = await contextB.newPage()

  await pageA.goto(serverUrl)
  await pageA.fill('input[placeholder="Name"]', 'Alpha')
  await pageA.click('button:has-text("Continue")')
  const codeLocator = pageA.locator('[data-testid="room-code"]')
  await expect(codeLocator).not.toHaveText('—', { timeout: 5000 })
  const code = (await codeLocator.innerText()).trim()

  await pageB.goto(serverUrl)
  await pageB.fill('input[placeholder="Name"]', 'Bravo')
  await pageB.click('button:has-text("Join Room")')
  await pageB.fill('input[placeholder="Code"]', code)
  await pageB.click('button:has-text("Continue")')
  await expect(pageA.locator('text=Bravo')).toBeVisible({ timeout: 5000 })

  await seedGame(serverUrl, code, monopolyRentSeed)

  // Bravo is current and owes doubled rent on Boardwalk.
  await expect(pageB.locator('[data-testid="sidebar"]')).toBeVisible({ timeout: 5000 })
  const baseRent = monopolyRentSeed.board[39].rent![0]
  const doubled = baseRent * 2
  await expect(pageB.getByText('$' + String(doubled))).toBeVisible({ timeout: 5000 })
  await expect(pageB.getByRole('button', { name: 'Pay Rent' })).toBeVisible()
  await expect(pageB.locator('[data-testid="event-entry"]').filter({ hasText: /owns the full color group/ })).toBeVisible()

  await expect(pageA.locator('[data-testid="waiting-for"]')).toContainText('Bravo')

  // Paying transfers exactly the doubled amount.
  await pageB.getByRole('button', { name: 'Pay Rent' }).click()
  await expect(pageB.locator('[data-testid="player-card"]').filter({ hasText: 'Bravo' })).toContainText('$1.4K')
  await expect(pageA.locator('[data-testid="player-card"]').filter({ hasText: 'Alpha' })).toContainText('$1.1K')
  await expect(pageB.locator('[data-testid="event-entry"]').filter({ hasText: /paid \$100 rent to Alpha/ })).toBeVisible()
})
```

Notes on the assertions:

- The doubled amount is derived from the fixture's board (`50 * 2 = 100`) and
  asserted via the visible `$100` in the rent prompt (`formatMoney(100)` is
  `$100`).
- `getByText('$100')` is unique on the page at prompt time (player cards show
  `$1.5K` / `$1K`, not `$100`).
- The doubling message is seeded into `eventLog` because the seed lands in
  `Resolving` — `ResolveSpace` will not run again (the decision already
  happened). The message is part of the scenario's history, exactly like the
  bankruptcy fixture's pre-computed rent.
- Money deltas: Bravo 1500 − 100 = 1400 → `$1.4K`; Alpha 1000 + 100 = 1100 →
  `$1.1K`. The `MoneyChange` float animation also renders `-$100`/`+$100` inside
  the cards, but `toContainText('$1.4K'/'$1.1K')` targets the persistent card
  text.
- The paid-rent log text is `Bravo paid $100 rent to Alpha`
  (`resolveLogEntry` formats `amount` as `$100`).

### 4. Verification

1. `npm run print-monopoly-rent-seed` → regenerates the fixture.
2. `npm run typecheck` → passes (all 3 TS projects).
3. `npm run lint` → passes.
4. `npm run test:unit` → passes.
5. `npm run build` → produces `dist/` (required by the e2e server fixture).
6. `npx playwright test e2e/monopoly-rent.spec.ts` → the new test passes.
7. `npx playwright test e2e/seed.spec.ts` → regression check (existing
   bankruptcy seed still passes).

## Out of scope

- No production code changes: the doubling rule, UI, and seeder already exist.
- No changes to existing e2e tests.
- This e2e test does not re-verify the doubling computation inside the reducer
  (that is covered by `src/logic/__tests__/rent.test.ts` and
  `gameReducer.test.ts`); it verifies the full server + UI pipeline for the
  doubled-rent scenario: prompt amount, doubling log message, and money
  transfer.
