# Trade E2E Scenario Expansion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add 26 seeder-driven e2e tests (14 positive + 12 negative) to `e2e/trade.spec.ts` covering the full trade scenario matrix, plus 7 new generated seed fixtures and 3 TradeModal unit tests.

**Architecture:** Extend the existing generated-fixture pattern (`scripts/print-trade-seed.ts` → `e2e/fixtures/*.ts`) with 7 new `createSeededState` scenarios, then add tests to the existing `e2e/trade.spec.ts` driving the real UI over the `serverUrlTrades` server. Three negatives use a mid-game re-seed to bypass client-side guards so the server-side rejection is reachable. No production behavior changes.

**Tech Stack:** Node `tsx`, TypeScript, Playwright, Vitest. No new dependencies.

## Global Constraints

- No TS `enum` (`erasableSyntaxOnly`); `verbatimModuleSyntax` on → `import type` for type-only imports; `noUnusedLocals`/`noUnusedParameters` on.
- Semicolons: `src/logic/*`, `src/data/*`, `server/*`, `scripts/*` use them; `e2e/*`, `src/components`, `src/hooks`, `src/net` omit them. Match the file being edited.
- e2e specs and fixtures must NOT import `src/logic/*` or `src/data/*` at runtime (Playwright's ESM loader rejects bare JSON imports there). `import type { GameState }` is safe. The spec may import `./fixtures`, `./helpers/seed`, the generated fixtures, and `import type { Browser, Page } from '@playwright/test'`.
- Generated fixtures carry a `// GENERATED by \`npm run print-trade-seed\` — do not edit by hand.` header and are produced by running the script — never hand-edited.
- `e2e/` is not in any `tsc -b` project; e2e gates are `npm run lint` + Playwright. `npm run build` (tsc -b + vite build) is required before any e2e run (`dist/` is served by the e2e server).
- Wire values (message types, action types, phases, log keys) never change.
- `seedState` (`server/gameServer.ts`) overwrites the seeded `tradesEnabled` with the room's own value — the same seed works on flag-on and flag-off servers.
- Seeds must satisfy `validateStateStructure` (`src/logic/seed.ts`): 40 spaces; `turnOrder` a permutation of player ids; `currentPlayer` in `turnOrder`; owned spaces match each player's `properties`; `Waiting` requires `pendingAction === null` and `dice === null`; money non-negative. `validateStateForRoom` requires `players.length === joined slots`, `players[i].id === i`, `currentPlayer` connected or a bot.
- Money formatting compact `Intl.NumberFormat` (`src/data/currency.ts`): 1100→`$1.1K`, 1250→`$1.3K`, 1150→`$1.2K`, 1350→`$1.4K`, 50→`$50`, 0→`$0`.
- Stripes (`src/data/players.ts`): Alpha `#E74C3C`→`rgb(231, 76, 60)`, Bravo/Droid `#3498DB`→`rgb(52, 152, 219)`, Charlie `#2ECC71`→`rgb(46, 204, 113)`. Droid sits at id 1, so it shares Bravo's stripe color (color comes from the generated seed).
- Board names (en): `board.space.1`="Salvador", `3`="Rio", `5`="TLV Airport", `6`="Tel Aviv", `8`="Haifa", `9`="Jerusalem", `12`="Power Company".
- i18n log keys (en): `event.tradeProposed`="{{from}} proposed a trade to {{to}}", `event.tradeAccepted`="{{from}} and {{to}} completed a trade", `event.tradeRejected`="{{to}} declined {{from}}'s trade offer", `event.tradeProposalRejected`="{{from}}'s trade offer to {{to}} was rejected — it is no longer valid", `event.tradeCancelled`="{{from}} cancelled their trade offer to {{to}}".
- The `TradeInboxModal` renders **offerer-relative** labels under both "You offer" and "You request" regardless of who is viewing.
- `GameView.tradeCount` = `pendingTrades.filter(tr => myPlayerId === null || tr.fromId === myPlayerId || tr.toId === myPlayerId).length`; the sidebar badge span renders only when count > 0.
- `TradeModal` clamps cash inputs to `Math.max(0, Math.min(value, playerMoney))`; `Propose` is disabled for empty trades. Offer cash input is `input[type="number"]` `.nth(0)`, request is `.nth(1)`.
- Player-card Trade button: rendered in the hover popup only when `player.id !== currentPlayerId && tradesEnabled`, `disabled` when `!canTrade` (includes `!player.bankrupt`).
- Modal scoping: never click a bare "Cancel" outside the `[data-testid="trade-offer"]` card when the offerer's inbox is open (offer card + footer both say Cancel); use `.last()` for the footer.

async function createRoom(page: Page, url: string, name: string): Promise<string> {
  await page.goto(url)
  await page.fill('input[placeholder="Name"]', name)
  await page.click('button:has-text("Continue")')
  const codeLocator = page.locator('[data-testid="room-code"]')
  await expect(codeLocator).not.toHaveText('—', { timeout: 5000 })
  return (await codeLocator.innerText()).trim()
}

async function joinByCode(page: Page, url: string, code: string, name: string): Promise<void> {
  await page.goto(url)
  await page.fill('input[placeholder="Name"]', name)
  await page.click('button:has-text("Join Room")')
  await page.fill('input[placeholder="Code"]', code)
  await page.click('button:has-text("Continue")')
}

async function joinRoom(host: Page, guest: Page, serverUrl: string): Promise<string> {
  const code = await createRoom(host, serverUrl, 'Alpha')
  await joinByCode(guest, serverUrl, code, 'Bravo')
  await expect(host.locator('text=Bravo')).toBeVisible({ timeout: 5000 })
  return code
}

async function joinThree(host: Page, pageB: Page, pageC: Page, serverUrl: string): Promise<string> {
  const code = await createRoom(host, serverUrl, 'Alpha')
  await joinByCode(pageB, serverUrl, code, 'Bravo')
  await expect(host.locator('text=Bravo')).toBeVisible({ timeout: 5000 })
  await joinByCode(pageC, serverUrl, code, 'Charlie')
  await expect(host.locator('text=Charlie')).toBeVisible({ timeout: 5000 })
  return code
}

async function addBot(page: Page): Promise<void> {
  await page.click('button:has-text("Add Bot")')
  await expect(page.locator('text=Droid')).toBeVisible()
}
