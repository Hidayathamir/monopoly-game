# Seed-Driven E2E Tests Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace room-setup/Start/turn-playing dances with `POST /seed` in 5 e2e tests so they run faster and deterministically.

**Architecture:** A generated `e2e/fixtures/initial-state.ts` (built by a new `npm run print-initial-state` script from `createSeededState`) supplies the 40-space board and card decks; `e2e/helpers/seed.ts` gains `buildWaitingState`/`seedWaitingGame` that assemble compact `Waiting` GameStates from it and POST them via the existing `seedGame`. `GameServer.seedState` additionally calls `driveBots()` so a seeded bot turn auto-plays. Then 4 tests in `e2e/multiplayer.spec.ts` and 1 in `e2e/monopoly.spec.ts` switch to seeding.

**Tech Stack:** Node `tsx`, TypeScript, Playwright, Vitest. No new dependencies.

**Design doc:** `docs/superpowers/specs/2026-08-18-e2e-seed-driven-tests-design.md` — read it for the rationale (especially "Finding 1" and "Finding 2" which motivate the fixture and the server change).

## Global Constraints

- No TS `enum` anywhere (`erasableSyntaxOnly`); use `const` objects + derived union types. `verbatimModuleSyntax` is on — type-only imports must use `import type`. `noUnusedLocals`/`noUnusedParameters` are on.
- Semicolons: `src/logic/*`, `src/data/*`, and `server/*` use them (match the file being edited); `e2e/*`, `src/components`, `src/hooks`, `src/net` omit them.
- e2e specs must NOT import `src/logic/*` or `src/data/*` at runtime — Playwright's ESM loader rejects the bare JSON imports there (`board-data.json`, `cards-data.json`). `import type { GameState }` and value imports from `src/types/game.ts` are safe (`types/game.ts` has no imports).
- The seeded state's `currentPlayer` is a server slot index; `validateStateForRoom` requires `players[i].id === i` for every joined slot and `players.length === joined slots`.
- `seedState` preserves the room's own `tradesEnabled`; a `Waiting` seed must have `pendingAction === null` and `dice === null`.
- Wire values (message types, action types, phases) never change.
- Bot slot names come from `BOT_NAMES` in `src/data/bots.ts`; the first bot added to a room is `Droid`.
- `npm run build` = `tsc -b && vite build` (needed before any e2e run; `dist/` is served by the e2e server). `npm run test:unit` = vitest. `npm run test:e2e` = Playwright.

- [ ] **Step 1: Write the helper**

Replace the contents of `e2e/helpers/seed.ts` with (no semicolons, matching the file):

```ts
import type { GameState, Player } from '../../src/types/game'
import { GamePhase } from '../../src/types/game'
import { INITIAL_BOARD, INITIAL_CHANCE_DECK, INITIAL_COMMUNITY_DECK } from '../fixtures/initial-state'

export async function seedGame(url: string, code: string, state: GameState): Promise<void> {
  const res = await fetch(`${url}/seed`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ code, state }),
  })
  if (!res.ok) {
    const body = (await res.json().catch(() => null)) as { message?: string } | null
    throw new Error(`seed failed (HTTP ${res.status})${body?.message ? `: ${body.message}` : ''}`)
  }
}

export interface SeedWaitingPlayerSpec {
  id: number
  name: string
  money?: number
  isBot?: boolean
}

export interface SeedWaitingOptions {
  players: SeedWaitingPlayerSpec[]
  currentPlayer: number
  turnOrder?: number[]
}

export function buildWaitingState(opts: SeedWaitingOptions): GameState {
  const players: Player[] = [...opts.players]
    .sort((a, b) => a.id - b.id)
    .map((p) => ({
      id: p.id,
      name: p.name,
      money: p.money ?? 1500,
      position: 0,
      properties: [],
      passedGo: true,
      inJail: false,
      jailTurns: 0,
      bankrupt: false,
      getOutOfJailFreeCards: 0,
      isBot: p.isBot ?? false,
      botControlled: false,
    }))
  return {
    phase: GamePhase.Waiting,
    players,
    turnOrder: opts.turnOrder ?? players.map((p) => p.id),
    currentPlayer: opts.currentPlayer,
    board: INITIAL_BOARD,
    chanceDeck: INITIAL_CHANCE_DECK,
    communityDeck: INITIAL_COMMUNITY_DECK,
    freeParkingPot: 0,
    dice: null,
    doublesCount: 0,
    lastMoveSteps: null,
    eventLog: [],
    pendingAction: null,
    justBoughtSpaceId: null,
    builtThisStop: false,
    reconnectGrace: null,
    pendingTrades: [],
    nextTradeId: 0,
    tradesEnabled: false,
  }
}

export async function seedWaitingGame(url: string, code: string, opts: SeedWaitingOptions): Promise<void> {
  await seedGame(url, code, buildWaitingState(opts))
}
```

Players are sorted by `id` so `players[i].id === i` (the `validateStateForRoom` requirement). `INITIAL_BOARD`/decks are read-only consts shared across all seeds.
